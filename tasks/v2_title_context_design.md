# 第二十六批：标题上下文的窄方案

状态：方案先冻结，两轮真实对照后否决当前生产接线；基于 `61ee2df`。

第二十五批合并标题改变块长、词频和候选分配，出现跨模式回退。因此本批保持解析、
分块、原文区间和 section/page 硬边界不变，只测试召回完成后的重排输入视图。

## 数据与职责

- 来源：候选现有 `heading_path` / `block_kind` 结构事实。它们由分块器产生，请求 metadata
  不能伪造；不从 query 猜主体，不从邻块/上一页抓文本，不额外读父块。
- 格式：`标题路径（仅定位信息）：…` 与 `正文：…` 分开。模型看到的定位信息不是可引用证据。
- 上限：最多 6 级，每级 80 字符，总标题 256 字符。超过上限整条回退原文，不截断名称；
  缺失/空白/非字符串/未知块类型同样回退。page 即使携带标题也不借标题扩大上下文。
- 返回：原 ID、正文和 start/end 不改；评分只认正文中的完整 quote。标题前缀含事实而
  正文没有时不得获得证据覆盖。模型排序结果按原始候选索引映射，不返回合成视图。
- 生命周期：复用现有模型 Port、客户端和进程闸门；不增加模型调用层、数据库或持久化字段。

## 冻结的实验

三个变体：plain（现有正文）、headings（完整路径）、ancestors（仅祖先，去掉路径末项）。
不在看到结果后增加规则或修改标签。原始集指纹 77b1547c… 与挑战集 76d06b53… 分开。
每个数据集/后端/召回模式只捕获一次生产候选池，快照身份、正文、区间和结构事实；
三种变体对同一池、同一查询调用真实 reranker，交错执行顺序并记录输入成本与阶段耗时。
原始生产重排作为采集核验，不混入配对均值。不得因模型失败而改用替身或删查询。

在 InMemory 和既有 Milvus 测试命名空间比较 dense/keyword/hybrid；原生集合由调用方
精确清理并复核既有基线。CLI 常规路径仍只用独立内存，不引入生产存储写入开关。
page/section、重复正文不同路径、异常 metadata、纯标题事实、前缀证据泄漏用手写回归与
缺陷注入验证；不把合成 page 测试宣称为 PDF/OCR 质量验收。

采纳条件：硬不变式全部保持；两个数据集、各模式的证据@1/3/5 无回退，且至少改善一个
已知缺口；电话/授权码/DBQ/原始恢复步骤等关键查询不得因前缀而失去正文证据。
只改善均值而出现关键回退不采用。权重 unknown、作者标签和合成语料仍限制结论；
不能凭此直接开启生产默认配置或关闭 M4-T10/H/I。

本批不先改变 embedding 输入：这会改变索引向量语义，需固定策略身份、重建边界及恢复
协议，不能通过“原文字符串→标题”映射猜上下文（相同正文可出现在不同文档/section）。
若后续有必要，再基于明确的 PlannedChild 身份提出独立方案。

## 结果

两轮、12个冻结池的72个配对组均完成。两种路径都会让电话事实的正确标题块被
不含号码的适用范围块挤掉，原文证据@1下降；完整路径还有备份主体混淆。当前不接入
生产，仅保留实验工具与回归。具体取舍与波动见
[第二十六批报告](../docs/evaluations/title_context_20261025.md)。
