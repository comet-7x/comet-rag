# MinerU 证据持久化、页内标题与恢复边界

2026-10-27。结论：**证据包归独立S3命名空间；正文索引仍归DocumentStore，
TaskStore只保存有界恢复意图。** 原计划复用既有MinIO，但该目标已确认不满足条件
发布门禁，后续按[持续维护部署方案](object_storage_deployment.md)验收新候选；没有
因此切换服务或引入新依赖。本轮在`evals/pdf/`实现本地证据包和Store协议原型，
真实PostgreSQL及既有真实解析产物验证通过；没有生产runner、API或配置接线。
后续独立S3适配已完成验证，但当前目标MinIO的条件PUT首次创建返回404、已存在时
返回200并覆盖测试字节，**未通过生产发布门禁**。有界读取可用；本机参考实例写入
通过不替代目标验收，见[最新S3协议](mineru_s3_evidence.md)。
结果见[验证记录](evaluations/mineru_evidence_20261027.md)，采集协议见
[V1设计](mineru_v1_design.md)。

## 现有原语的能力与缺口

| 现有位置 | 可复用能力 | 本轮决定 |
|---|---|---|
| TaskStore／TaskContext | CAS、执行尝试围栏、context写入、条件删除、游标分页 | 保存固定小检查点，不存整份正文／内嵌图片／账本 |
| DocumentStore | revision身份、计划指纹、父块正文／区间及metadata、激活／abandon／purge | 父块只存小引用，保持原文区间；不造“账本父块”占用索引计数 |
| S3兼容存储 | 既有MinIO为最初候选，实测条件写不兼容 | 保留不可变包协议，改为独立命名空间验收新候选；生产中间件仍未更换 |
| S3Loader | 来源URI解析、下载及生命周期 | **只有读取，没有上传或发布接口**；不能把它包装成已存在的ArtifactStore |
| StoredRevision | generation／status等字段 | 当前不返回draft metadata，也没有通用只读get_revision；不以reserve充当无副作用读取 |

现有revision context默认预算为32MiB，但不是给原生PDF JSON预留的空仓库；还要容纳
移交与恢复数据。即使本次19.56MB原生产物能单独塞入，也不能因此把它复制进每次
Task CAS、父块或向量metadata。证据属于文档版本，不能依赖普通任务TTL存活。

## 证据包及引用

每份包包含且只包含三个文件：

1. `structured_content.json`：已经完成来源绑定的原生字节，最多32MiB。
2. `ledger.json`：同一映射策略生成的正文、完整物理页、逐片段证据、独立图像解读和
   资产摘要，最多16MiB；正文8MiB、解读2MiB等既有语义预算继续生效。
3. `manifest.json`：版本、策略、revision三元组、来源SHA、物理页数、canonical以及
   前两份文件的精确长度／摘要，最多64KiB。最后发布，作为可核验的提交标记。

小引用包含revision三元组、source SHA、pages、canonical SHA和manifest SHA。
对象前缀为`evidence/v1/<kb摘要>/<source摘要>/<revision摘要>/<manifest摘要>`；不把本地
路径或任意业务字符串直接拼为对象路径，也不跨KB做共享删除或泄露来源。生产部署
还须将该前缀置于明确的新命名空间／bucket权限中，前缀散列本身不是访问控制。

**读取从持久化的小引用开始。** 先核验manifest精确摘要和全部身份，再有界读取两份
文件、校验长度／摘要，并从原生JSON重新映射，对照整个账本。没有manifest、文件少／
多、错revision、错canonical、账本被修改或超限都失败。重新计算一套文件摘要不能
把改过的账本变成原文；bool与int在JSON比较中也不能混用。摘要证明字节绑定，不能
认证可被同一写入者任意替换的数据库、模型工件、OCR正确性或人工标签。

本地`publish_bundle`只建新目录，文件fsync后最后写manifest并同步目录；`load_bundle`
必须通过后才确认检查点。它验证了文件协议，不模拟整个S3服务。本地manifest发布
也可能在写入或fsync中断，出现文件不等于通过完整读取；重试应回读核验。

S3适配复用已安装客户端的条件写／checksum能力，拒绝覆盖同key的异字节；
同key已存在时完整核验后才认作幂等成功。当前botocore模型有`IfNoneMatch`与
`ChecksumSHA256`参数，但目标MinIO兼容性、持久性、TLS、权限和故障接收仍需真实
验收。独立适配现已交付，目标兼容性实测未通过，不能接生产；没有新增可写对象Port，
也没有假定S3Loader能完成这项工作。

父块的既有metadata可容纳约几百字节的小引用；原文定位继续使用start/end及revision。
本轮在内存和PG中以`evidence_reference`演练其快照／跨连接读取，未改生产字段或schema。
正式接线必须只在父块的受保护写入点放引用：不能透传请求metadata伪造引用，也不能
直接放到document_metadata，后者会经当前IndexPlanner传播到向量子块。零父块、空文字
页及独立解读仍在证据包中；不能仅靠“能查到父块”推断整包生命周期。

## 页与标题的表示

保留两份互补事实：账本的完整pages保存物理页（含空文字页），evidence保存每个原生
片段的heading_path、类别和原文区间。独立索引视图使用**页内连续标题区间**：

- 一页可有多个`page_section`，每个区间同时带page_number与heading_path。
- 页变、标题变、重复标题再次出现、原文／auxiliary类别变都产生新边界。标题路径可
  跨页继承，但块本身不能跨页；不补缺失标题，不把跳级层次猜成不存在的祖先。
- 先验证原始evidence覆盖非空正文，再合并同页同标题同类别区间。否则中间漏项可能
  被一个更大的连续区间掩盖，给未登记文字错误附上标题。
- 标题不重复塞入正文、不额外插入`#`，原canonical、正文及Unicode字符偏移不变。
  新视图只改变索引结构；真正索引计划指纹仍需涵盖策略与块事实。
- 复用既有原子Chunker、split_blocks的区间和覆盖守卫。引用仍须逐原生证据片段校验，
  不能把一个合并索引区间当成原生quote；图像解读不进入原文索引视图。

现有PageChunkingStrategy要求页号严格递增，不直接接收此视图；现有Normalizer也仍
维持旧page行为。本轮没有把同页多个section伪装为多个page块、修改生产策略或默认
参数。HTML表格仍可能被原子预算切开，本轮不据结构通过宣称表格证据单元完整。

## 恢复意图的持久化顺序

`AsyncCaptureJournal`是独立协议原型，复用现有`_put_context`的CAS及TaskContext围栏；这些
内部模板原语没有扩展。专用采集演练context总量最多8KiB，固定检查点只增不改：

| 检查点 | 必须先满足 | 确认丢失后的处理 |
|---|---|---|
| intent | 来源／端点／revision身份已确定，尚未发POST | 已存在则不再次授权POST，即使可能根本没发出去 |
| observed | intent匹配，取得安全task_id和source_file_id | 保存已观察身份；不以此声称来源已经核验 |
| source_verified | 远端SHA／大小／名称／用途实际校验通过 | 身份不变；恢复时重新访问远端仍须校验服务及来源 |
| bundle_intent | source_verified，来源及revision匹配 | 在发布对象前保存精确manifest引用，失败可按该引用回读 |
| bundle_committed | 已按bundle_intent完整回读包 | 相同引用幂等确认；不再请求模型或重写同名对象 |

围栏、前置身份、不可覆盖规则和整份context预算都在同一CAS中检查。旧attempt迟到、
取消中、并发写入或损坏前置不能覆盖较新事实。对象发布与数据库确认没有跨系统事务；
因而bundle_intent在对象之前，确认在回读之后。远端POST也不与数据库原子提交，不能
因此声称exactly-once；宁可保留不确定，也不把重复解析伪装成任务幂等。

源核验标记是“已经做过HTTP核验”的检查点，不能由这个bool反向认证HTTP真实性。
原型没有自动对接采集器，调用顺序在故障测试中演练；尚未注册runner、Task kind或
cron，也未改变任何Task持久化字段。8KiB是独立演练预算，不覆盖现有32MiB入库预算。

`guard_capture_task_deletion`保留任何相关marker，包含null／损坏记录；终态、force、
年龄和bundle确认都不自动解除。守卫只有明确传给删除调用才生效，生产TaskService
本轮未接线。原型没有“force清意图”入口；将来释放前必须将不确定处置、证据引用和
审计决策独立归档，不能让唯一恢复来源随普通Task TTL消失。

## 不确定任务与远端产物

| 观测 | 允许的下一步 | 禁止据此推断 |
|---|---|---|
| 明确尚未提交、没有intent | 建立新intent后首次提交 | 可以绕过意图直接POST |
| intent已写但无task_id／回包丢失 | 保留、告警、人工查受控服务记录；必要时显式建立关联的新任务 | 源SHA去重等于任务幂等，可以自动重提 |
| 已观察ID但来源未绑定 | 只读核对身份；不做取消或文件删除 | 某个看起来合法的ID必属于本来源 |
| 来源已绑定且queued／running | 每次有界只读轮询，或明确取消；等待占统一预算 | 本地超时／取消等于远端结束 |
| completed、未保存证据包 | 仅对原任务做有界产物读取与核验，不重新POST | completed保证产物可用或永久可下载 |
| 异常产物／错摘要／错页 | 保留回执和错误、人工核查；不因错误反复采集 | 可以放宽校验、换格式或重提直到成功 |
| canceled／failed／partial | 保留观测，交给上游保留策略；partial不成为完整证据包 | 已删除源字节、共享blob或GPU资源 |
| 404／服务重启 | 人工区分索引丢失、过期和其他原因；已验证本地证据仍可读 | 从未提交、远端已排干或允许重提 |

`remote_disposition`只返回建议，默认不重提、不删远端文件、不确认排干；它没有实现
HTTP续传、扫描服务所有任务或自动采纳同SHA的其他任务。现有采集CLI也不会因新增
这个建议函数而自动恢复任务。异常产物默认被原采集器清理，留回执；本轮没有悄悄
增加无限期保存坏文件的隔离区。

固定MinerU4.0.12源码及独立FileStore实验确认：

- 默认终态资源保留为86400秒，扫描间隔300秒；显式参数／
  `MINERU_API_RETENTION_SECONDS`可改，0禁用自动回收。不能从默认值推断当前远端配置。
- 文件视图、输入／输出共享blob和job是不同生命周期。DELETE file只移除视图；有其他
  视图或运行引用时底层blob仍保留。终态清理完成后才开始输出保留计时。
- 正在运行／清理的任务不按这个终态TTL强杀。过期回收不是900秒采集deadline的替代品，
  也不提供严格的墙钟删除时间；持续故障需运维告警和人工处置。
- job／file索引在内存，重启后旧ID可消失；持久化upload目录也不能恢复这些索引。

因此首个生产范围应**不由Comet主动DELETE files，也不按整个upload目录清理**，优先
使用上游已有保留／引用机制并验收实际部署值。未知任务只能人工处置，不能通过源码
默认TTL保证已经排干。官方边界见[MinerU HTTP API](https://opendatalab.github.io/MinerU/usage/http_api/)。

## 自有证据包的保留和接线门禁

远端是暂存工作区，自有证据包是版本证据。active、可恢复的staging／ready以及不确定
意图关联的包都不自动TTL；retired／abandoned也不能只据年龄删除。现有revision GC只
负责父块／向量／墓碑，没有证据对象删除承诺。先复用其精确身份与墓碑协议，再单独
验收对象回收的保留守卫和迟到写补偿；当前没有可靠的通用只读墓碑查询，故本轮不加
对象自动GC。原生JSON与账本按同一包保留，不能删原生文件后继续声称V1回读完整。

未来补偿扫描复用TaskStore的(kind, created_at, task_id)游标，单页8条、每轮30秒候选，
不得为扫空而无限循环；新记录和损坏记录都需要持续重访。次数、最老不确定年龄、
占用字节和上游保留配置应可观测，达到部署批准的配额时拒绝新增采集并告警。本轮
没有启用调度、配置配额或宣称这套运维闭环已经运行。

正式接线前依次验证：可写对象适配的条件发布和有界回读；父块引用保护与只读证据
读取；页内标题策略的质量对照；已知ID恢复与不确定处置；对象保留／回收及告警。
涉及新Port、Task字段、向量metadata或迁移时仍按spec边界单独确认。独立人工标签、
不可变模型工件、上游semaphore警告与正式新命名空间验收保持原有门禁。

对象层后续验证见[S3协议](mineru_s3_evidence.md)和[MinIO诊断](evaluations/minio_diagnosis_20261027.md)：
当前目标为已核实的2023构建，条件写不兼容的原生原因已定位，发布门禁继续拒绝。
修正后的上游源码候选在隔离环境通过协议、读quorum故障与进程终止恢复，但不是
官方生产发布，且上游仓库已声明不再维护。应先确定可持续维护的实际部署方案与
迁移／回退验收，再推进上述引用保护；没有因此自动接入生产或开启对象GC。
