# MinerU V1 独立采集器验证

2026-10-27。**完成独立采集与故障验证，未接入生产、未切换配置。**
实现位于`evals/pdf/`，只依赖项目已有httpx、闸门、线程排干和离线映射能力；没有新增
SDK、引擎依赖、Port、Task字段或向量schema。协议／运行方式见
[设计与预算](../mineru_v1_design.md)，可复核的计数及摘要见[机器记录](mineru_v1_capture_20261027.json)。

## 实现边界

- `mineru_v1.py`编排单文件异步采集，借用进程级AsyncClient和有界Gate；每次运行的
  ID、预算、回执单独保存，不在共享采集器上串状态。
- `_v1_protocol.py`校验版本、能力、原生任务／文件身份与不可混用的状态；
  `_v1_files.py`管理私有输入快照、临时产物和原子回执；`capture.py`只负责独立CLI装配。
- 原生原始字节入口只提交一次，advanced／auto／all，只请求structured_content。
  预检health与tiers；观察到task_id先fsync回执，再核验远端源文件SHA，随后轮询。
  产物的文件元数据、实际字节数、SHA、完整页和严格映射全部通过才发布。
- 统一900秒预算从本地准备／排队前开始，含5秒取消预留；上传300秒、单请求60秒、
  本地Gate等待30秒均取剩余预算。控制响应256KiB、产物32MiB、累计36MiB，检查声明
  和实际流；不接受压缩、重定向或响应给出的其他地址。源PDF最多100MiB。

取消后排干本地线程及关闭文件，再释放Gate；已核验来源的已知任务才尝试原生取消。
不确定提交不会自动重提，没有来源身份也不盲目取消。取消回执只记录acknowledged，
`remote_drained`始终不作肯定。不可中断本地I/O和失败记账可能晚于截止，不追加网络
宽限。进程强杀、磁盘永久故障、远端后台回收和重启续传不在成功保证内。

## 故障复现与改正

**暖缓存的大文件提交丢回包是实际发现的问题。** 起初按官方原始字节入口传可选
`sha256sum`。冷缓存采集成功，但暖缓存60页上传出现httpx ReadError，采集器没收到
task_id，服务端却已创建并最终完成任务。核对固定4.0.12源码：SHA命中时可跳过读取
上传体、提前回包并关闭连接；本次httpx0.28.1组合没有可靠收到它。失败实验保留，
没有以重试成功掩盖。官方接口形态见[MinerU HTTP API](https://opendatalab.github.io/MinerU/usage/http_api/)。

最小修正是去掉可选SHA查询参数，完整上传本地已核验的私有快照，再核对原生源文件
metadata的服务端SHA。没有实现上传三阶段、换协议或自动重提。最终7／60页及原生
CLI冒烟均通过；模型能力未因此改变。该问题不推广到未经测试的MinerU/httpx版本。

真实故障注入还包括：

1. 转发真实提交直到服务端返回202，再主动丢弃响应。确认只提交一次；采集器留下
   submission=unknown、task_id=null，不用猜测ID。测试工具另外观察服务端已建任务，
   并显式取消自己的任务；这不是采集器具备孤儿任务发现能力。
2. 60页占用远端执行时提交7页，给予2秒总预算（内部预留0.8秒取消）。确认任务处于
   queued，预算到达后取消回执为acknowledged，保留remote_drained=false。
3. 本地关闭失败注入最初得到2个红测：成功已发布后close失败会推翻返回或遮蔽原错。
   改为关文件是成功前置，失败清理收集附加错误且保留主因；两例重跑通过。

真实服务没有人为返回畸形JSON；这类网络／产物异常通过MockTransport和可控流注入：
ID／文件错配、能力缺失、partial／未知状态、摘要／长度错、缺页、错误类型、非有限
数字、压缩体、无Content-Length的越界流、累计轮询超限、回执写失败、发布时超时、
重复取消和写线程未结束等。失败不得留下成功产物，也不关闭借来的客户端。

## 验证结果与剩余门禁

- 定向101 passed：采集器／CLI 55、严格映射46，0.60秒。
- 全量unit：3736 passed、16 skipped、389 deselected、1 xfailed，10.00秒。
  前一轮静默完整运行10.28秒，更早一轮10.32秒；严格`<10s`门禁仍未关闭。最慢项
  仍以既有并发／取消等待为主，不为此削弱断言或将外部服务测试移入unit。
- 全仓ruff通过，pyright零错误，格式及diff检查通过。
- 对实际实现制作10个独立缺陷版本：自动重提、跳过两处SHA、去单次／累计流量限制、
  deadline重置、取消额外宽限、回执顺序错、先发布再关闭、恢复SHA缓存短路参数。
  原测试均明确失败。另注入CLI缺失来源字段的KeyError，新增输入守卫测试失败；共11项。

真实采集后才补充了Gate满载错误分类与CLI缺字段校验，均有零网络测试；真实采集
所用源码快照单独保留，未把后来变化伪称为再次GPU实测。API停止前确认本次独立
进程创建的12个任务都到终态（8 completed／4 canceled），PID及监听端口随后退出；
9919未停止。关停仍有一次上游resource_tracker semaphore警告，不能宣称无资源泄漏。

下一步先明确生产证据账本的持久化位置、页内标题表示及不确定任务／远端文件保留
策略。现有page块仍会丢标题路径，本工具没有替换Normalizer或Extractor。独立人工
复核、固定工件、上游生命周期警告和正式新命名空间验收继续按原发布门禁处理。
