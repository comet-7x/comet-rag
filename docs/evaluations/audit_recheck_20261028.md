# 外部审查报告复核

2026-10-28。原报告针对 d3fd7a8 附近的树，且自述未跑 integration/e2e、未完整读
解析器部署和契约测试。本轮以源码、可执行复现和真实隔离中间件分别核验；不把原报告
的“六位审查者”或总体健康判断当证据。修复范围随本次收口冻结，不把建议全部升级
为当前必须改的架构需求。最终验证见[收口记录](mineru_wiring_20261028.md)。

| 原项 | 复核结果及本轮处理 |
|---|---|
| 1 同源并发 flat 重入库删新块 | 确认。按 KB/source 复用 TaskStore 唯一键+CAS 围栏，覆盖 count/upsert/delete 全窗口；不同来源仍独立。未知写保留围栏，不按 lease 自动接管。真实跨连接验证。 |
| 2 空提取/空分块覆盖旧版本 | 确认。提取、恢复 indexing 和 revision 准备拒绝空结果；普通分块复用既有覆盖守卫；保留既有块/active 指针。 |
| 3 默认 Word XML 命名空间崩溃 | 确认。列表读取改用命名空间 URI QName；带/不带列表均回归。 |
| 4 单次慢续租误失败 | 确认。容忍一次超时、记录日志，下次成功复位；连续超时仍停止执行，硬 Store 错误/失去租约不吞掉。不是无期限 continue。 |
| 5 所有 API 缺认证 | 参考 API 无全局身份入口属实。新证据入口单独加 KB 范围鉴权；其余仍要求可信网络/网关。完整 RBAC/OAuth 是 spec 非目标，正式公网部署另验收。 |
| 6 负降级阈值永久拒写 | 确认。配置预检要求有限正数、失败率≤1、级别非递减；不是自动解释负数为关闭。 |
| 7 metadata 无界放大 | 确认。共享 API/服务请求模型要求有限 JSON、UTF8 序列化≤64KiB。此限制不代替 HTTP 请求体/代理上限。 |
| 8 进程池连接数相乘 | 属实，属于部署容量。每进程共享 Database 池，默认最多30；按 API+worker 总进程预算，不能误算成每服务/仓储一池。本轮不改变默认。 |
| 9 本地文件无限读取 | LocalLoader 本身只 stat/交付路径，并非直接读10GB；通用文本解析下游仍需本地预检上限。新 MinerU 有100MiB快照上限；不扩展所有格式路径。 |
| 10 legacy revision 判活 fail-open | 原报告误判设计边界。显式 active=None 且没有 revision 标记的 legacy 内容按兼容契约可见；缺 lookup 键、null/空/畸形标记失败关闭。已有特征/契约测试保留。 |
| 11 未闭合 Word 字段吞显示文字 | 确认。段尾输出已出现的结果，不输出字段指令；不据此宣称完整嵌套字段栈支持。 |
| 12 文本框、嵌套表、OLE | 当前遍历确有覆盖缺口；本轮未另做真实样本复现/完整支持。简单递归 w:object 无法解析二进制 OLE，须独立定义有界语义，列入后续已知限制。 |
| 13 包含 SEQ 的交叉引用误作题注 | 确认。只认 SEQ 指令 token，REF/NOTEREF 不按子串误判。 |
| 14 KB 列表逐个 count | 确认性能问题。本轮不加无界 gather；后续决定有界并发或列表是否返回精确计数。 |
| 15 cron 胜者随机导致游标总在0 | 推论不成立：实例状态在非连续胜出之间也保留，不要求连续获胜。进程重启和动态 offset 的公平性仍是限制；重复提交有 SQL/Redis 成本，不是免费。 |
| 16 缺并发/空重入库回归 | 已补可重复调度的并发5块/1块与原有3块复现，空提取、空分块、持久化空draft及空revision负例。 |
| 17 health/tiers 缺直接故障测试 | 确认测试缺口。补兼容成功及错类型/版本/能力/分层失败的直接参数测试。 |
| 18 S3 文档引用失效路径 | d3fd7a8 的当前协议文档已指向正式模块；冻结历史评测仍保留旧路径，不全局替换历史事实。 |
| 19 三个无效配置旋钮 | env 为描述性字段；connect_timeout/Redis.timeout 当前未接下游超时语义。后续单独决定接线或删除，不本轮静默改变兼容面。 |
| 20 total 实为本页长度 | 确认易误导；后续定义 has_more/total 契约，不靠无界扫描或擅自扩展核心 Store 接口。 |

flat 围栏修复同源并发丢块，但不把旧 ordinal ID 改成原子 revision：多窗口写入失败
仍可能留下混合版本。需要版本原子替换时使用已验收的新命名空间 revision 路径。
旧服务或绕过 TaskStore 的写入者不能共享这项保证；发布前所有参与写者必须升级。
未知 RPC 围栏保留会停止该来源后续写入，这是明确的可恢复处置需求，不是静默成功。

原报告列出的其余小项未逐项完成经验验证，不将它们标为已修复。没有删除失败测试、
改向量 schema、新增核心 Store 方法或引入第三个向量后端。
