# 标题上下文对照：第二十六批

本批先冻结[窄方案](../../tasks/v2_title_context_design.md)，比较仅增强重排输入的标题
上下文。解析、分块、embedding、索引和服务返回正文保持不变；实验工具不进入 wheel。
结论：两种标题路径均出现持续的原文证据回退，未进入生产。

## 设计与证据边界

模型输入可以带定位信息，引用证据仍来自规范正文的半开区间。候选自身的
`block_kind=section` 与 `heading_path` 是唯一结构来源；不读取父块、邻块或上一页正文。
page/未知类型、异常路径、超过 6 级/每级 80 字符/总标题 256 字符时整条回退原文，
不截断名称。三个变体为 plain（原文）、headings（完整路径）、ancestors（去掉末项）。
祖先视图只有根标题时保持原文；DOCX 路径中的加粗标记照实保留。

原始集与挑战集沿用上一批的标签和生成规则，指纹分别为
`77b1547c8df1560faddfb5b6f23e6ae1818f42cff7fce6546ac3801687f51c21` 与
`76d06b536676b174e892ce162bce33713638c4b75d1cb5979d563de68dbf9557`。
两套数据分开计分；没有根据排名改题、改证据或增加临时规则。作者自审不代替独立标注。

每个数据集/后端/模式顺序调用一次既有 collect 与 RetrievalService，记录实际 reranker
收到的候选身份、原文、区间和 metadata；请求失败或服务降级直接使采集失败。
每个固定候选池分别调用真实 reranker，查询之间循环轮换三个策略的执行顺序。
排序索引映射回原候选，供应商回传的正文不作为引用来源；冻结池有独立 SHA-256，
输入视图的 metadata 深复制，不允许模型污染快照。标题前缀即使含完整答案也不得计为
正文证据。所有候选先检查原文与可见性，最终 run 再交既有严格评分器核验。

真实配置沿用项目现有模型项，embedding 4096 维，重排与向量均经过可用/有限值探测。
模型为 Qwen/Qwen3-VL-Embedding-8B 与 Qwen/Qwen3-VL-Reranker-8B，权重版本 unknown。
每个比较共用同一客户端和进程闸门；录制器借用客户端，外层退出栈负责关闭。
InMemory 精确召回与 Milvus 2.6.22 Chinese 原生召回分别报告；原生只使用既定测试库
的随机前缀，父块与激活状态仍在独立内存，不能称为实际生产部署验收。

每组 top_k=5、fetch_k=50，hierarchy child=100、overlap=15、parent=300；比较 dense、
keyword、hybrid。输入增加量以字符计，不是 tokenizer token 数。配对耗时仅测重排 RPC，
采集耗时才是完整 search；二者不能混算，更不能据单遍实验承诺稳定 P95/QPS。

预先约定采纳条件：两个数据集、两种后端、全部模式的 evidence@1/3/5 无回退，且至少
改善一个已知缺口；关键电话/授权码/DBQ/恢复步骤不得因前缀丢失正文证据。均值改善
不足以覆盖关键回退。embedding 上下文涉及向量语义与重建，未在本批实验中混入。

三个具体失败可以逐块解释：

- phone：plain 首位是 heading_fact[0,16)，含 6118；两种标题视图首位变成
  同文档[16,58)的适用范围，正文只有“该号码用于夜间值班联络”，不含号码。
  定位信息让正文看似相关；文档 Recall@1 不变，原文证据@1 从 1 变 0。这正是前缀泄漏
  会掩盖的回退；电话标题仍在候选中，不能用“没删原文”证明质量无损。
- star_long_backup：完整路径在第一轮六种召回组将正确的星桥[671,701)替换为
  星桥归档[644,677)的 06:30/400 天；仅祖先路径这一例未回退。前缀不是主体硬过滤。
- rto_pair：两种路径偏向 harbor_long[1309,1398)的否定交叉引用，含星桥30分钟而
  没有港湾90分钟。首位证据由 0.5 变 0，部分模式前三却由0.5变1；不能只报前三收益。

也有收益：starcloud_rto 在多数比较中从星桥30分钟纠正为星桥云75分钟，
star_archive_backup 的完整路径从无证据变为首位有证据；cloud_pair 有部分前三收益。
这些收益没有抵消上述关键回退。star_steps 仍常把星桥云流程当星桥流程，不能声称
标题已解决近似实体混淆。auth_code/DBQ-71/DBQ-72 的正文证据没有因本批策略丢失。

模型输入成本也有增加：挑战集 memory/dense 的31条查询共1466个候选视图，
完整路径额外67413字符，祖先路径额外48527字符；原文组为0。这些是重复查询的输入
总量，不是索引增量或 token 数，不能把同一块在多个查询中出现当作多个独立样本。

## 重复性与第二轮

第一轮12次候选采集中共有294次 search，36个配对组/882条查询重放。采集时与原文
重放相比，28条查询前五排序不完全相同，但 E@1/3/5 均未改变。没有供应商原始分数
或固定权重/服务端执行证据，不能断言是某种浮点或批处理原因。
因此对完全相同的12个冻结池再跑第二轮，而不是重新召回后挑高分。

## 实现、回归与后续

临时视图函数放在仓库 evals，未修改包运行时。录制器只接受带身份的文本候选并深复制；
借用客户端而不关闭它。重放验证全部候选身份、active/KB、原文区间与排列/有限值，
将排序索引映射回原始 Hit。新增 `real --title-context` 仅连接模型，默认独立内存索引；
失败不退回替身、不产生健康摘要，外层退出栈关闭模型。

回归涵盖异常/超限路径、page 隔离、重复正文不同主体、空池、轮换顺序、前缀含答案不
算证据、索引映射、metadata 污染、录制错配和模型故障。六项独立副本注入分别放开
page 借标题、取消单级长度保护、忽略模型排列、共享可变 metadata、浅借录制输入、返回模型前缀视图，
均产生预期目标 failure，无收集/夹具 error。工作区未注入缺陷。

优先下一步仍是独立标签和可公开真实资料/PDF/page、固定部署权重与 tokenizer/token
预算、ANN 对精确召回，而非继续按本组合成题调标题规则。若另试 embedding 上下文，
需用明确 PlannedChild 身份携带结构事实，并独立设计策略身份/新 revision 重建及失败
恢复；禁止按正文字符串反查标题。若要让标题事实成为返回证据，需要显式的原文片段
引用与多区间预算方案，不能把合成前缀混入单一 span。

原始运行、候选池、差异、路由探测和清理证据在 `/tmp/comet-v2-batch26-validation/`；
不提交模型地址、凭据、原始结果或生成 DOCX。真实模型仅单机单遍重复两轮，权重未知、
作者标签/合成长文仍限制结论。M4-T10/H/I 与生产质量门禁保持未完成。
