# MinerU4 structured_content 映射评估

2026-10-27。结论：**原生结构可用于新的正文与证据契约，但直接投影到当前生产接口
会丢失页内标题和逐片段证据类别。** 下一步限定为独立V1采集器，生产提取器、配置、
依赖和索引保持不变。完整映射及预算决定见[设计边界](../mineru_v1_design.md)。

本轮复用[上一轮固定Pro2605/9919的真实产物](mineru4_pro2605_20261027.md)，未再次
调用模型，未将离线回放描述成新的一轮解析或检索质量实测。逐份重新核对源PDF字节、
完整物理页、原生版本、规范化、候选片段引用及页内分块。原始输入SHA-256与来源锁
绑定，用户正文和账本只保存在Git忽略目录。

所有页记录完整；60页投影的物理4页没有提取文字，但图片与解读身份仍保留，不能
把它写成漏页或原PDF空白。背封文字保留，标为auxiliary；引用须显式许可。
图像body不进入提取文字正文，caption/footnote与其父块关联。开启分析不保证提取
文字canonical稳定：两份正文差10字节，候选块分类与分组也不同，不能共用旧span。

两份60页正文均通过13/13来源关键词探针、表1表头与24/24指定数值、3/3背封探针；
SP800-144物理52页的两条指定表2编号／完整题名也通过。这是前轮作者拟定探针的
回放，不是独立人工验收、全部OCR准确率或本轮模型质量提升。

保留了原生HTML和Markdown表体。60页8个表体中旧HTML区间工具只覆盖2个；NIST
的1/7个表体均不是其覆盖的HTML表。不能将其余表算成丢失或行预算通过。语义数值
探针复用独立环境已有Markdown解析器按原行列检查，没有给项目添加解析依赖；原生
表体对应整段候选片段，但不保证现有800/1600字符分块能完整返回整表或长行。

标题路径保存在实验账本，并通过跨页继承、跳级退栈及不移动正文的回归。当前
MarkdownDocumentNormalizer生成的page块heading_path仍为空；这项特征化测试明确
阻止“提取成功＝生产标题引用已保真”的结论。分离image/chart类别也不能发现上游
将读图推断误分类为table的情况，账本不授予“原PDF已核准”状态。

## 实现和复现

[structured.py](../../evals/pdf/structured.py)负责纯离线验证、映射、来源身份与引用校验；
[structured_audit.py](../../evals/pdf/structured_audit.py)负责有限读取、来源锁和审计输出。
没有复制上游文字、公式、列表、图片或表格renderer，也不导入MinerU/Docvortex。

```bash
uv run python -m evals.pdf.structured_audit \
  --input /path/to/structured_content.json \
  --source-lock /path/to/inputs.json --sample squid \
  --out /tmp/comet-structured-new-run
uv run pytest tests/unit/test_pdf_structured.py
```

source-lock沿用前轮实验的samples：id、源文件path、SHA-256、bytes及总物理页数。
输出必须是新目录；损坏输入在建目录前失败，不留下成功summary。projection.json
含新正文、逐页片段、来源证据、独立解读和不含地址的资产摘要。summary.json只作
统计和诊断；两者都是离线产物，不写Task.context、DocumentStore或向量metadata。

用户资料及回放产物位于 `.artifacts/v2-validation/mineru-structured-20261027/`，仓库
只保存[不含用户正文的聚合记录](mineru_structured_20261027.json)。

## 故障和验证

新增46项零网络回归覆盖缺页／重复／bool页号、来源计数、版本／形态错配、bbox、
标题层级、说明类型、重复JSON键、非有限数字、字节／片段预算、UTF-8区间、旧
canonical、跨页／跨片段引用，以及不具备资格的辅助文本和图像解读。另确认文件在
stat之后增长仍会被实际读取预算拦下。

七项实现反向注入全部使对应测试按预期变红：接受bool页号、放过尾页缺失、混入
图像解读、用栈深代替level、身份不绑定证据类别、默认放行辅助文本、移除输入限长。
注入使用实际模块源码的独立副本，测试不改期望值，生产文件未被临时覆盖。

全仓ruff与pyright通过；默认unit为3681 passed、16 skipped、1 xfailed，389项其他
标记未运行。最终pytest耗时9.85秒；本轮此前还观察到10.58秒及输出精度为10.00秒
的运行，不据单次通过或四舍五入后的临界值关闭稳定小于10秒的门禁。没有重跑与
本次离线工具无关的中间件或E2E套件。

单进程60页映射另测Python tracemalloc峰值78584430字节；它包含有限输入读取与
映射，不是RSS、并发容量或服务负载基准。输入19.6 MB的大部分仍是图片地址，
忽略地址只能缩小持久化正文，不能免除接收／JSON解码成本。
