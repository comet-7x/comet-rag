## 映射契约

本轮仅覆盖已核验的MinerU4.0.12固定布局PDF；不声称所有4.x版本兼容。
structured_content不是Middle JSON：原生块content已由上游转为Markdown字符串，
但没有Middle JSON的schema身份，不能交给同一个反序列化器。协议形态、版本、来源
PDF摘要及总物理页数分别核验，不能由任意一个字段代替其他检查。

| 原生事实 | 实验映射 | 不作的推断 |
|---|---|---|
| pages/page_idx | 必须从0完整连续，对照外部来源锁；映为1基物理页，空正文页仍保留 | 不从印刷页码、文字相似度或full标志猜页 |
| text/list/ref_text/page_footnote | 复用原生content及现有NFC/换行规范化，记录来源指针和字符区间 | 不另做OCR、断词修复或跨页续文合并 |
| doc_title/paragraph_title | 显式level维护标题栈，退出同级及更深标题，路径可跨页继承 | 不凭栈深补不存在的标题；不因正文长得像标题而重判 |
| table | 保留原生HTML或Markdown表体，caption/footnote分别定位并关联同一父块 | 不转换表格、不拆解再造单元格、不自动拼跨页续表 |
| image/chart content | 作为独立模型解读保存，排除在提取文字正文及其引用账本之外 | 不将读图估算表改标为原文表格 |
| visual captions/footnotes | 保留各组内顺序和原生文本、可用bbox，与父块关联 | 不借父bbox冒充缺失的子块坐标 |
| header/footer/page_number | 保留在可审计正文，标记auxiliary，不继承业务标题路径；默认引用校验不接受 | 不继续静默丢背封，也不自动纠正其分类 |
| image_source | 仅记录所在页、指针、字节数与摘要 | 不解码、访问或持久化data URI／远端地址 |

原型正文按原生页序、块序拼接。视觉块内固定为body、captions、footnotes；原生结构
已经分组且删除原index，不能据此恢复组间原PDF阅读顺序。这是显式的新拼接策略，
不是上游DEFAULT/FULL Markdown。标题文字不额外加 `#`，level与path保存在账本。
图片页没有提取文字时允许正文为空，但仍有物理页、资产及可能的解读；空正文不等于
原PDF空白，也不能默认用模型描述补进正文。整本无可索引正文时离线审计明确失败。

本轮支持上述12种顶层类型；未验收的code/equation/index、新字段或新版本明确失败，
不静默丢块。列表及原生行内样式作为已渲染内容保留，不尝试重建其内部AST。

## 证据身份与引用

每个候选片段保存：源PDF SHA-256、物理页、JSON pointer、父块pointer、原生类型、
body/caption/footnote角色、heading_path、可用bbox及新正文字符区间。pointer中的块
序号是本次产物数组位置，不冒充上游稳定ID；bbox仅定位原生块区域，不是quote的
逐字矩形。区间按Python Unicode字符计数，不是UTF-8字节或token。

新canonical身份绑定策略版本、源PDF摘要、逐页正文和整个证据账本；另存正文摘要和
原始JSON摘要。只变未消费的图片地址不会改变文字证据身份；只变页号、类别或标题
路径，即使全文文字相同也须改变身份。新旧原生Markdown、开关图像分析的两次产物
和不同策略之间不迁移旧span。本轮开／关分析的提取正文也确实存在差异。

引用校验必须同时满足：指定本轮canonical、指针存在、类别获准、区间位于同一候选
片段、quote逐字相等。不能跨页或把表头／表体／注释的多个片段拼成不存在的一段；
跨片段答案需列多份证据并保留同表关系。辅助块须显式许可；图像解读不在该账本中。

`extraction`表示内容来自提取器的文字／表格类别，**不表示已经独立核对原PDF**。
上游若将推断误标为table，单靠类型不能检测出来；特征化测试保留这一限制。caption
和footnote也只是提取结果。`verify_quote`只核对新canonical和来源类别，不认证OCR、
事实关系、精确数值、人工标签或发布质量。

## 当前接口的实际限制

现有ExtractedDocument可以承载上述逐页文字；但MarkdownDocumentNormalizer优先
生成page块，不同时保留页内各标题路径。NormalizedDocument块不可重叠，现有
PageChunkingStrategy还要求page_number严格递增，不能直接把同页多个section当作
多个page块塞入。代码已用特征化测试确认：实验账本有标题路径，旧规范化结果为空。

现有生产链也没有为这份逐片段证据／解读账本定义持久化和引用读取契约。将它塞入
任意metadata或Task.context既不能证明会完整保存，也可能突破既有context预算。
因此本轮没有新增Port、Task字段、向量metadata或生产normalizer；这些不由采集器
顺手决定。若后续要接生产，先选定可复用的存放位置和页／节组合表示，再按仓库边界
评审涉及的契约变更。独立标签、不可变模型工件及新命名空间验收继续保留。

## V1 采集器的最小范围

1. 只连接明确配置的单个自部署API，复用现有TLS／回环端点规则和应用级httpx客户端。
   预检 `/v1/health` 的4.0.12版本与structured_content能力，另查 `/v1/tiers` 的advanced；没有能力就失败，不回退旧
   `/health`、旧补丁或另一个格式。模型URL不作为文档API地址。
2. 单次一个PDF，通过原生 `POST /v1/tasks` 原始字节入口提交；显式advanced、
   ocr_mode=auto、page_range=all、output_formats=structured_content，并提供filename、
   Content-Length。上传前生成私有临时快照并核验来源锁的大小和SHA；不传local路径、远端来源URL、callback或模型覆盖参数。
   优先复用上游便捷提交，不再实现一套上传三阶段协议。
3. 收到task_id后先保存与来源摘要绑定的本地回执，再轮询原生任务状态，仅下载唯一
   成功文件的structured_content产物。源文件及输出文件分别经原生file metadata核验
   ID、用途、名称、长度和SHA；只有来源核验后的任务才允许取消。不请求默认Markdown、Middle JSON、ZIP或图片，
   不加入解压／图片持久化链。partial、未知状态、错配ID／文件／格式都不能算成功。
4. 从已校验ID构造同源固定路径，不盲信响应中的任意URL；最小单实例范围拒绝重定向。
   Router、云端跨源预签名、批量、持久化任务服务及SDK直连不在首批范围。
5. 总deadline从本地闸门排队前开始，覆盖上传、远端排队、轮询、下载及落盘前核验；
   复用有界MinerU闸门，阶段预算取配置与剩余时间的较小值，不为每次轮询重置计时。
   本地等待仍最多30秒且受总预算约束，远端排队占用同一总预算。900秒内预留最后5秒
   用于取消，正常工作最多895秒；单请求60秒、上传300秒，都受剩余正常工作时间约束。
6. 不确定的提交响应丢失不能自动重提来冒充幂等；上传SHA去重不等于解析任务幂等。
   超时／取消保留已知task_id和明确的不确定状态；如仍有预算才尝试原生取消。请求
   断开或取消响应成功不证明远端已排干。重启后API任务索引也不保证可恢复，不能把
   新API当成TaskStore的替代品。首批不自动接生产重试。

真实暖缓存实验确认：4.0.12原始字节入口带可选`sha256sum`且命中缓存时，会跳过读取
上传体并提前返回；本次httpx0.28.1的大文件上传丢了回包，但任务已创建。因此采集器
不发送该可选参数，始终完整上传已核验的快照，再核对服务端计算的源SHA；没有加入
隐藏重试、条件回退或上传三阶段协议。该观测限定于已验证版本和组合。

上述范围已实现于独立工具，真实7/60页、提交回包丢失和排队超时均已验证。
生产同步／异步入口若最终接线，仍分别使用Foo/AsyncFoo及原生httpx执行模型，不从
应用导入MinerU SDK。可参考官方[V1 API](https://opendatalab.github.io/MinerU/usage/http_api/)
与[输出契约](https://opendatalab.github.io/MinerU/reference/output_files/)，字段仍以固定
4.0.12源码和实际服务能力为准。

## 已落实的隔离预算

以下仅用于独立采集，不修改当前16 MiB生产响应上限。

| 对象 | 限制 | 实施边界 |
|---|---:|---|
| 来源PDF | 100 MiB | 大小预检及快照实际复制核验；只接受普通文件 |
| JSON产物 | 32 MiB | 实际原始字节流限长；不只信Content-Length；拒绝压缩 |
| 单次控制响应 | 256 KiB | health、tiers、提交、轮询、文件元数据及取消独立限长 |
| 一次采集累计接收 | 36 MiB | 把全部轮询及产物计入，避免小响应无限累积 |
| 提取正文／独立解读 | 8 MiB／2 MiB | 分开计数，不把data URI算进可索引正文 |
| 单块文本 | 1 MiB | 标题、正文、说明、图像解读分别校验 |
| 页／块／证据片段 | 512／20000／50000 | 源页数、实际数组和映射结果分别检查 |
| 每组caption或footnote | 128 | 防止一个视觉块无限放大账本 |
| 总时间 | 900秒 | 闸门、上传、排队、下载共享；不自动延长 |

接收只接受identity编码、固定媒体类型及不重定向的同源路径；CLI关闭HTTP传输重试、
代理环境与隐式认证重试。响应按64KiB流块读取，产物直接写临时文件，不在内存累计
整份HTTP响应。越界块不落盘；已观察的流块仍计入累计接收，因观察粒度可能多读最多
一个64KiB块，这不是网卡或内核的硬流量限制。Content-Length缺失仍检查实际长度，
存在时同时核对声明及实际长度。控制JSON与产物均拒绝重复键、非有限数字及深度解析失败。

标准JSON解析先建立对象，
再检查块数等语义限制；32 MiB不是硬内存限制。60页输入实测Python tracemalloc峰值
78584430字节，不含全部native/RSS；并发2会叠加。大图密集资料仍可能被明确拒绝，
不能承诺任意512页都能通过。若要更小传输，应优先争取上游提供资产省略／外置能力，
本轮不为规避上限引入流式JSON解析器、ZIP或新依赖。

本地快照、落盘、JSON映射和关文件走可排干线程桥。取消后等线程结束才释放文件与
Gate，先关闭本地资源再发布completed；产物摘要、页域、映射或最后deadline校验失败
都会清理本次产物并记录失败。原子替换仅保证单份回执写入，不提供文件与远端事务；
进程被强杀可能留下part或产物，消费前必须核对completed回执及其大小／摘要。

总deadline覆盖准备、排队、网络、核验和发布，但不能抢占不可中断的本地文件系统
调用。线程排干及失败记账可能晚于截止时刻；不为此延长网络预算或在截止后继续解析
任务。剩余接收预算不足、来源未核验、ID未知、取消超时／回包异常时，保留不确定性，
不宣称远端已清理。原生API自身任务索引、服务端产物删除和后台资源回收不由本工具证明。

## 使用与结果

```bash
uv run python -m evals.pdf.capture --url http://127.0.0.1:28995 \
  --source-lock /path/to/inputs.json --sample nist145 --out /tmp/new-v1-capture
uv run python -m evals.pdf.structured_audit \
  --input /tmp/new-v1-capture/structured_content.json \
  --source-lock /tmp/new-v1-capture/source_lock.json --sample nist145 \
  --out /tmp/new-v1-audit
```

来源锁形态为`{"samples":[{"id":"nist145","path":"/absolute/source.pdf","sha256":"64位小写摘要","bytes":85781,"pages":7}]}`。
必须提供实际源字节及物理页数；不能从服务端的full标记反推来源事实。输出必须是新目录，
权限0700；源快照与产物临时文件0600。`receipt.json`记录已观察ID、来源绑定、实际
接收字节、错误和取消结果；公开错误不回显端点、正文或凭据。输出含原生内嵌资产与
本地来源路径，应按资料自身敏感度保管。可用`--api-key-env NAME`读取已有令牌环境变量。

`--url`是独立文档API，不是9919上的VLM地址；CLI不读取config.yaml或.env。
一个CLI进程复用一份AsyncClient和有界Gate（并发2／等待16）；程序化并行调用必须
共用同一进程级Gate，不能每次新建。采集器借用客户端，不负责关闭它。首次提交回包
丢失返回`submission_unknown`，保留目录，禁止把重新运行当作幂等恢复；本轮没有重启
续传、持久化任务调度或远端孤儿任务自动发现。
